## روش‌های آزموده‌شده و روشی که واقعاً جواب داد

برای اینکه مشخص باشد کدام اقدام مؤثر بوده، مسیرهای آزموده‌شده در دو دسته ثبت می‌شوند.

**روش‌هایی که جواب ندادند:**

۱. حذف پوشه‌ی وابستگی‌ها و قفل نسخه‌ها و نصب مجدد:

```cmd
rmdir /s /q node_modules
del package-lock.json
npm install
```

۲. پاک‌سازی کش npm و نصب مجدد:

```cmd
npm cache clean --force
npm install
```

۳. به‌روزرسانی ابزارها و شروع تازه:

```cmd
npm install -g npm@latest
npm -v
```

و همچنین نصب مجدد نسخه‌ی LTS از Node.js از سایت رسمی و سپس اجرای `npm install`.

هیچ‌یک از این مسیرها خطای `ERESOLVE` را برطرف نکرد؛ چون ریشه‌ی خطا در ناسازگاری اعلام‌شده‌ی نسخه‌های peer بود، نه در فایل‌های خراب، کش آلوده، یا نسخه‌ی قدیمی npm.

**روشی که جواب داد:**

```cmd
npm install --legacy-peer-deps
```

پس از چند دقیقه که نصب با موفقیت تمام شد:

```cmd
npm run dev
```

نکته‌ی عملی مهم: هر دستور باید در خط جداگانه و مستقل در CMD اجرا شود. چسباندن چند دستور در یک خط باعث خطای گمراه‌کننده‌ای مثل `The system cannot find the file specified` می‌شود که در تصویر اولیه دیده شد و ربطی به خرابی CMD یا ترمینال نداشت.

## چرا --legacy-peer-deps مشکل را حل کرد

طبق مستندات رسمی npm، پرچم `--legacy-peer-deps` رفتار npm را به نسخه‌های ۳ تا ۶ برمی‌گرداند: نصب به‌جای رد کردن کامل درخت به‌خاطر ناسازگاری `peerDependencies`، آن تضاد را نادیده می‌گیرد و مسیر نصب را باز می‌کند. خود npm تصریح می‌کند که «استفاده از `legacy-peer-deps` توصیه نمی‌شود، چون قرارداد `peerDependencies` را که متا‌وابستگی‌ها ممکن است به آن تکیه کنند، اعمال نمی‌کند» ([مستندات پیکربندی npm](https://docs.npmjs.com/cli/v11/using-npm/config/)).

به بیان ساده، مشکل این پروژه این بود که نسخه‌ی اعلام‌شده در `peerDependencies` یکی از پکیج‌ها (که معمولاً در اکوسیستم React و ابزارهای UI رخ می‌دهد) با نسخه‌ی نصب‌شده در درخت وابستگی هم‌خوان نبود. npm نسخه‌های جدیدتر به‌طور پیش‌فرض این ناسازگاری را خطا می‌داند؛ در نتیجه نصب متوقف می‌شود. با این پرچم، npm از آن مرحله عبور می‌کند و پکیج‌ها همان‌طور که در `package.json` و `package-lock.json` تعریف شده‌اند نصب می‌شوند.

سه تنظیم مرتبط که دانستنشان کمک می‌کند:

- `strict-peer-deps` — اگر `true` باشد و `--legacy-peer-deps` هم تنظیم نشده باشد، هر تضاد در `peerDependencies` به‌عنوان خطای نصب در نظر گرفته می‌شود.
    
- `force` (`--force`) — گزینه‌ی جایگزین است، اما شدیدتر عمل می‌کند و حتی تناقض‌های دیگر را هم نادیده می‌گیرد؛ برای این پروژه لازم نبود.
    
- `.npmrc` — هر تنظیم خط فرمان را می‌توان به‌صورت پایدار در فایل `.npmrc` پروژه ثبت کرد تا در نصب‌های بعدی نیازی به تایپ پرچم نباشد.
    

**هشدار فنی:** این پرچم خطا را پنهان می‌کند، حذف نمی‌کند. اگر بعداً رفتار غیرمنتظره‌ای در کامپوننت‌های UI یا تایپ‌ها دیدی، اولین گزینه‌ی بررسی، همین ناسازگاری نسخه‌های peer است؛ راه‌حل پایدار، هم‌تراز کردن نسخه‌ها در `package.json` و سپس نصب بدون پرچم است.

## شواهد موفقیت: خروجی Vite و آدرس دسترسی

پس از نصب موفق، `npm run dev` در واقع اسکریپت `vite` را در ریشه‌ی پروژه اجرا می‌کند و سرور توسعه بالا می‌آید. در اجرای این پروژه، سرور روی پورت **۳۰۰۰** بالا آمد و آدرس زیر در ترمینال نمایش داده شد:

```text
http://localhost:3000/
```

عدد پورت ثابت و از پیش تعیین‌شده نیست. طبق مستندات Vite، مقدار پیش‌فرض `server.port` برابر **۵۱۷۳** است و اگر این پورت اشغال باشد، Vite به‌طور خودکار پورت بعدی آزاد را انتخاب می‌کند؛ مگر اینکه `server.strictPort` روی `true` تنظیم شده باشد ([گزینه‌های سرور Vite](https://vite.dev/config/server-options)). به همین دلیل، در این پروژه پورت ۳۰۰۰ دیده شد: یا در `vite.config` تنظیم شده است یا پورت‌های پیش‌فرض در آن لحظه آزاد نبودند. بنابراین قاعده‌ی درست این است که همیشه همان آدرسی که ترمینال چاپ می‌کند در مرورگر باز شود، نه یک آدرس حدسی.

یک هشدار زرد رنگ هم در خروجی دیده شد که مربوط به یک گزینه‌ی منسوخ در فایل تنظیمات Vite بود. این هشدار اجرای سایت را متوقف نمی‌کند و بی‌خطر است؛ صرفاً پیشنهاد می‌کند کلید قدیمی با معادل جدیدش جایگزین شود.

**تأیید نهایی موفقیت:** وقتی آدرس ترمینال در مرورگر باز شد و رنگ‌ها، منوها و چیدمان واکنش‌گرای داشبورد همان‌طور که در AI Studio طراحی شده بود نمایش داده شد، یعنی هر دو مرحله — نصب وابستگی‌ها و راه‌اندازی سرور — درست انجام شده است.

## دستور نهایی و نکات نگهداری پروژه

برای بازسازی محیط از صفر، همین ترتیب کافی است و آزمودن مسیرهای دیگر ضرورتی ندارد:

گامدستورتوضیح۱`cd C:\Users\AMIR.AHF\Downloads\Website\fortiguard-admin-dashboard`ورود به پوشه‌ی پروژه؛ مسیر ابتدای خط باید همین باشد۲`npm install --legacy-peer-deps`نصب وابستگی‌ها با نادیده گرفتن تضاد peer؛ چند دقیقه زمان می‌برد۳`npm run dev`راه‌اندازی سرور توسعه۴باز کردن آدرس چاپ‌شده در مرورگرمعمولاً `http://localhost:3000/` یا `http://localhost:5173/`

- **هر دستور در خط جداگانه.** چسباندن دستورها در یک خط، خطاهایی مثل `The system cannot find the file specified` تولید می‌کند.

- **ثبت پایدار تنظیم.** با افزودن `legacy-peer-deps=true` به فایل `.npmrc` پروژه، نصب‌های بعدی بدون تایپ پرچم انجام می‌شوند؛ اما این محدودیت رسمی npm را دائمی می‌کند و بهتر است پس از به‌روزرسانی نسخه‌ها یک بار بدون آن امتحان شود.

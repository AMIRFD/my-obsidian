# 1        مبحث مطالب پایه

## 1-1    Docker **چیست؟**

داکر (Docker) یک ابزار سبک و انقلابی برای بسته‌بندی نرم‌افزارهاست که برنامه را به همراه تمام فایل‌ها، کتابخانه‌ها و تنظیماتش داخل یک «کانتینر» ایزوله قرار می‌دهد تا دقیقاً مانند یک پکیج آماده، بدون وابستگی به نوع سیستم‌عامل، روی هر سیستمی فوراً و بدون خطای «روی سیستم من کار می‌کرد» اجرا شود.

کاربردهای اصلی آن: راه‌اندازی سریع و آسان سرویس‌های ابزاری و دیتابیس‌ها (مثل n8n یا PostgreSQL)، یکسان‌سازی محیط توسعه و سرور پروداکشن، اجرای همزمان چندین سرویس مستقل (میکروسرویس‌ها) با مدیریت متمرکز منابع، و حذف درگیری‌های پیچیده‌ی نصب پکیج‌ها روی سرورهاست.

### **1-1-1**     **کاربرد** Docker

مثلا  وقتی برنامه‌نویس جدیدی به تیم اضافه می‌شود برای توسعه نرم افزاری که سازمان شما داره روش کار میکنه، باید ساعت‌ها یا حتی روزها وقت بگذارد تا چند نرم‌افزار، دیتابیس با نسخه دقیق، پکیج‌ها و تنظیمات محیطی را روی سیستم شخصی‌اش نصب کند. در این مسیر معمولاً با انواع خطاهای عدم سازگاری (Conflict) و تفاوت سیستم‌عامل‌ها دست‌وپنجه نرم می‌کند. حالا اگر ۱۰ نیروی جدید اضافه شوند، این چالش زمان‌بر و فرساینده ۱۰ بار تکرار می‌شود!

  سناریوی با داکر:

تمام معماری پروژه (کدها، دیتابیس و پیش‌نیازها) در قالب یک پکیج آماده (Container Image / Docker Compose) تعریف شده است. عضو جدید فقط داکر را باز کرده و با زدن یک دستور ساده (مثل docker compose up)، کل پروژه را در عرض چند دقیقه و بدون حتی یک خطای سازگاری، دقیقاً مشابه سرور اصلی روی سیستم خود اجرا و شروع به کار می‌کند.

### **1-1-2**     Kernel **داکر چیست و بر روی چه سیستم عاملی نصب می‌شود؟**

داکر از Linux kernel استفاده می‌کند. نیاز به سیستم عامل لینوکس داریم.

اما بر روی ویندوز هم قابل نصب است یعنی با نصب Docker desktop، ابتدا Linux kernel اجرا میشه و سپس داکر بر روی آن بالا میاد. چون ویندوز قابلیتی دارد به نام **WSL 2****. در** **WSL 2****،** یک **کرنل لینوکسی** در پس‌زمینه از طریق یک هایپروایزر بسیار سبک (Lightweight Hypervisor) اجرا می‌شود. وقتی داکر دسکتاپ اجرا میشه، آن در لینوکس WSL2 مستقر شده و اجرا میشه.

## 1-6    **تفاوت** Image **با** Container

### **1-6-1**     Image

یعنی یک پکیج از برنامه یعنی شامل پوشه‌ها، کتابخانه‌ها، سرویس‌ها که فقط خواندنی هستند و

### **1-6-2**     Container

به نسخه اجرا شده Image (که بالا توضیح داده شد) می‌گویند Container. یک لایه اختصاصی و مستقل روی Image می‌کشد و می‌گوید: «حالا هر تغییری می‌خواهی بده، ایمیج اصلی دست‌نخورده باقی می‌ماند.»

از قابلیتی به نام **Copy-on-Write** استفاده می‌کند

یک محیط ایزوله ایجاد میکنه

در VMware اگر به 5 تا لینوکس نیاز داشته باشید، باید 5 تا VM بسازید که هر کدام فضای هارد و مقدار رم و سی پی یو زیادی استفاده میکنند مثلا حجم هر کدام 5 گیگ میشود یعنی 25 گیگ فضای هارد شما پر میشه

در Doccker، هر 5 تا Container، فقط از همان یک Image استفاده می‌کنند. میاد فقط یک لایه سبک از Image که حجمش 5 گیگ است میسازد و حجم اولیه داخل Container صفر مگابایت است. حال اگر یک فایلی از Image را به واسطه Container بخوایم تغییر دهیم، فقط حجم همان فایل در بخش Container اضافه میشه یعنی فایل داخل Image یک فایل با حجم 1 مگ است، فقط همان یک مگ میشه حجم Container

برای درک این موضوع از دستور زیر استفاده کنید:

Docker ps -s

خروجی طبق تصویر زیر:

·      ستون SIZE شامل دو بخش است. خاب به در ردیف اول نگاه کنید.

  مقدار اولی (یعنی 4.1kB حجم مصرفی خود Container را نشان می‌دهد) دومی (یعنی Virtual 689MB حجم خود Image را نشان می‌دهد)

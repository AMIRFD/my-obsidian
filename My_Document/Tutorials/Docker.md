## 1-1    Docker **چیست؟**

داکر (Docker) یک ابزار سبک و انقلابی برای بسته‌بندی نرم‌افزارهاست که برنامه را به همراه تمام فایل‌ها، کتابخانه‌ها و تنظیماتش داخل یک «کانتینر» ایزوله قرار می‌دهد تا دقیقاً مانند یک پکیج آماده، بدون وابستگی به نوع سیستم‌عامل، روی هر سیستمی سریع، آسان و بدون خطای اجرا شود.

مثلا  برنامه‌نویس جدیدی به تیم اضافه می‌شود 
برای توسعه نرم افزار، باید ساعت‌ها یا حتی روزها وقت بگذارد تا چند نرم‌افزار، دیتابیس و پکیج‌های سازگار و... را روی سیستم شخصی‌اش نصب کند. که معمولاً با انواع خطاهای عدم سازگاری (Conflict) و تفاوت سیستم‌عامل‌ها و... دست‌وپنجه نرم می‌کند. حالا این یک نفر هست، اگر ۱۰ نیروی جدید اضافه شوند چی؟؟!!، این فرایند زمانبر باید ۱۰ بار تکرار می‌شود!

  راه حل به کمک Docker:

تمام معماری پروژه (کدها، دیتابیس و پیش‌نیازها) در قالب یک پکیج آماده (Container Image / Docker Compose) تعریف شده است. عضو جدید فقط داکر را باز کرده و با زدن یک دستور ساده (مثل docker compose up)، کل پروژه را در عرض چند دقیقه و بدون حتی یک خطای سازگاری، دقیقاً مشابه سرور اصلی روی سیستم خود اجرا و شروع به کار می‌کند.

### **1-1-1**     Kernel **داکر چیست و بر روی چه سیستم عاملی نصب می‌شود؟**
داکر از Linux kernel استفاده می‌کند
در ویندوز هم قابل نصب است اما با قابلیت WSL2 یعنی در ویندوز ابتدا Linux kernel اجرا میشه و سپس داکر بر روی آن بالا میاد و **WSL 2****،** که از طریق یک هایپروایزر بسیار سبک (Lightweight Hypervisor) اجرا می‌شود.

### دو اصطلاح کلی در Docker
یکی Image: همان پکیج‌های ما هستند که به راحتی از سایت https://hub.docker.com/ قابل دانلود هستند 
در اصل یک فایل فقط خواندنی مرده است
یا از طریق دستورات Powersheel مربوط به داکر، قابل دانلود هستند طبق زیر:
docker pull nginx:latest
دقت کنید که حتما باید با : تگ یا ورژن آن Image را مشخص کنید البته برای تگ latest اگر ننوشتین هم مشکلی ندارد یعنی فقط docker pull nginx کافی است

دیگری Container: همان محیط ایزوله‌ای هست که Imageها  درون آن قرار می‌گیرند
حالا هر تغییری می‌خواهی بده، ایمیج اصلی دست‌نخورده باقی می‌ماند
از قابلیتی به نام **Copy-on-Write** استفاده می‌کند
فایل های موقتی هستند و چون حافظه ندارند، اگر حذف شوند، تمامی تغییرات  تنظیمات انجام شده، حذف خواهد شد
میاد فقط یک لایه سبک از Image که حجمش 5 گیگ است میسازد و حجم اولیه داخل Container صفر مگابایت است
حال اگر یک فایلی از Image را به واسطه Container بخوایم تغییر دهیم، فقط حجم همان فایل در بخش Container اضافه میشه
حالبیش اینجاست که اگر یک ایمیج داشته باشیم 5 گیگ، وقتی تبدیل به  Container شود، حجم آن صفر مگابایت است. حال اگر یک فایلی از Image را به واسطه Container بخوایم تغییر دهیم، فقط حجم همان فایل در بخش Container اضافه میشه نه حجم کل ایمیج

## 1-1    Docker Compose**:**
در کل: هدیه‌ای به ادمین‌ها و توسعه‌دهندگان است تا از شر تایپ کردن طولانی‌ترین و پیچیده‌ترین دستورات `docker run` با کلی سوییچ `-e` و `--network` راحت شوند
ابزاری قدرتمند که به شما اجازه می‌دهد
